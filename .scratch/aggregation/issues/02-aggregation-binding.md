# Aggregation binding + wrapper: aggregate in `toOutcomesJson` / `toJson`, types

Type: task
Status: ready-for-agent
Blocked by: 01

## Question

Per ADR-0018, expose the aggregate through the napi binding and the wrapper:

- napi: `query_rich` and `resolve_rich` serialize the per-candidate `aggregate` object (when the query requests it) alongside the existing rich fields — `{outcome, ruleIds/winner, values, applicable, aggregate}` for matched/resolved candidates; absent for notMatched/invalid.
- Wrapper: no new methods — `query(...).toOutcomesJson()` and `resolve(...).toJson()` already carry it; verify the payload shape and add TypeScript types for the aggregate object if any are surfaced (the wrapper types `toOutcomesJson`/`toJson` as `string`, so the aggregate shape is documented in the README rather than typed).
- The query object passes through the existing input normalization unchanged (`aggregate` is just a query member).

Tests: node smoke — an `aggregate` query returns the aggregate object in the rich JSON; the mask path is unaffected; a query with `aggregate` through `queryAsync`/`resolveAsync` behaves identically.

Run: `cargo test --workspace`, clippy, and the node smoke/integration suites.

## Agent Brief

**Category:** enhancement
**Summary:** Serialize the core `aggregate` computation in the rich napi payloads and verify it through the wrapper.

**Current behavior:** `query_rich`/`resolve_rich` serialize per-candidate outcomes with rule ids, winner, values, and applicable; there is no aggregate member.

**Desired behavior:**
- Rich JSON gains a per-candidate `aggregate` object when the query requests it.
- The mask, `count()`/`summary()`, and all existing rich fields are unchanged.
- The wrapper needs no new methods; the README documents the aggregate shape.

**Key interfaces:**
- napi `query_rich` / `resolve_rich` serialization.
- The wrapper's existing `toOutcomesJson()` / `toJson()` terminals.

**Acceptance criteria:**
- [ ] `query_rich` carries `aggregate` for matched candidates when requested
- [ ] `resolve_rich` carries `aggregate` for resolved candidates when requested
- [ ] The aggregate is absent for notMatched/invalid candidates
- [ ] No new wrapper methods; `query()`/`resolve()` surfaces unchanged
- [ ] Node smoke verifies the aggregate payload through `toOutcomesJson`/`toJson`, and async parity
- [ ] `cargo test --workspace`, clippy, and the node smoke/integration suites pass

**Out of scope:**
- Changing the query/mask hot path
- A dedicated aggregate API
- Typed aggregate objects on the wrapper (rich JSON is a string)
