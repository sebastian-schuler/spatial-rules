# Aggregation core: `AggregateSpec` parse/validation + per-candidate computation over the applicable set

Type: task
Status: resolved

## Question

Per ADR-0018, implement the core aggregation computation:

- `Query` gains an optional `aggregate: Option<AggregateSpec>`.
- `AggregateSpec` = `{ count: bool, min: Option<String>, max: Option<String>, sum: Option<String>, avg: Option<String>, coverage: bool }` — each numeric function names its own rule-property field.
- Parse/validate in `Query::from_json`: unknown keys, non-boolean `count`/`coverage`, non-string numeric fields, or an empty `aggregate` → `SR_INVALID_QUERY`.
- Compute, per candidate, over the **applicable rule set** (the resolution primitive, ADR-0015):
  - `count` = applicable-set size;
  - `min`/`max`/`sum`/`avg` = numeric (Int/Float) aggregation of the named property across applicable rules; missing/non-numeric rules skipped; absent when nothing contributes;
  - `coverage` = `geodesic_area(candidate ∩ union(applicable rules)) / geodesic_area(candidate)`, via `BooleanOps::union` + `GeodesicArea`; point/multipoint candidates → `0`.
- Rich-path only: computed when `collect_ids` is set (lazy, alongside the rich JSON); the mask hot path is untouched. A per-candidate aggregate rides the existing rich evaluation — absent for notMatched/invalid candidates.
- Works uniformly across DE-9IM, `withinDistance`, and `$activeAt` predicates (they all feed the same applicable set).

Tests: spec parse/validation (unknown key, wrong type, empty), per-function correctness (hand-checked numeric + coverage), missing/non-numeric property skipping, absent-when-nothing-contributes, point-candidate coverage 0, single-rule coverage equals its overlap, aggregate absent for notMatched/invalid, mask/count/summary/winner/values unchanged.

Run: `cargo test --workspace` and `cargo clippy --workspace --all-targets` — green before commit.

## Agent Brief

**Category:** enhancement
**Summary:** Add a query-level `aggregate` spec computing per-candidate analytics (count / min / max / sum / avg / coverage) over the applicable rule set, rich-path only.

**Current behavior:** The rich path reports rule ids (query) and winner/values/applicable (resolution) per candidate; there is no analytics view and no way to compute min/max/coverage without shipping rule properties to the client.

**Desired behavior:**
- A query-level `aggregate` spec (strictly validated) requests the functions.
- The rich evaluation computes them natively over the applicable set, per candidate, and carries the result as an `aggregate` object in the rich JSON.
- The mask, `count()`/`summary()`, and resolution winner/values are unchanged.

**Key interfaces:**
- `Query` / `AggregateSpec` — parsed in `Query::from_json`, strict validation.
- The rich evaluation — a per-candidate aggregate computed alongside the applicable set.
- An `Aggregate` result struct carrying the requested fields.

**Acceptance criteria:**
- [ ] `aggregate` parses and validates strictly (unknown key / wrong type / empty → SR_INVALID_QUERY)
- [ ] `count` equals the applicable-set size
- [ ] `min`/`max`/`sum`/`avg` aggregate the named numeric property; missing/non-numeric rules are skipped; absent when nothing contributes
- [ ] `coverage` = union coverage via `BooleanOps::union` + `GeodesicArea`; point candidates → 0; single-rule coverage equals its overlap
- [ ] The aggregate is absent for notMatched/invalid candidates
- [ ] Works across DE-9IM, `withinDistance`, and `$activeAt` predicates
- [ ] Mask, `count()`/`summary()`, and resolution winner/values are unchanged
- [ ] `cargo test --workspace` and `cargo clippy --workspace --all-targets` are green

**Out of scope:**
- Per-rule aggregates across the batch (histograms)
- Any change to admission, resolution, or the mask hot path
- Wrapper/napi exposure (ticket 02)
## Answer

Implemented. core/src/aggregate.rs: AggregateSpec (strict from_json validation: unknown keys, wrong types, empty/all-false -> SR_INVALID_QUERY) + per-candidate Aggregate computed over the applicable rule set (count; min/max/sum/avg over a named numeric property, missing/non-numeric skipped, absent when nothing contributes; union coverage via BooleanOps::union + GeodesicArea, point candidates -> 0). Query gains an optional aggregate member + with_aggregate builder. Rich-path only; mask/winner/values unchanged. Works across DE-9IM, withinDistance, and $activeAt (all feed the applicable set).
