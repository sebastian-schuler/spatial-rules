# resolve() / resolveAsync() API: ResolutionResult terminals (napi + wrapper)

Type: task
Status: ready-for-agent
Blocked by: 02, 03

## Question

Per ADR-0015 and ADR-0014, resolution is a new surface, not a query flag:

- Rust core: expose the resolution path on `Engine`/`Ruleset` (mirroring `query`/`query_mask`).
- napi binding: `resolve(candidates, query)` returning a compact native mask (`0` no resolution, `1` resolved, `2` invalid); `resolveAsync` mirroring ADR-0009 off-thread.
- Wrapper: chainable `ResolutionResult` — `mask()`, `count()`, `summary()` derived in JS from the mask (zero rich cost); `toJson()` the one lazy native rich call returning per-candidate `{outcome, winner, values, applicable}`. Same query shape as `query()` (`spatial`/`where`/`excludeRuleIds`).
- `query()` and the hot mask path stay untouched.

Tests: mask semantics, lazy `toJson()`, async parity with `resolve()`, TypeScript type exports.

Run: `cargo test --workspace`, clippy, and the node smoke/integration suites.

## Agent Brief

**Category:** enhancement
**Summary:** Expose `resolve()`/`resolveAsync()` returning a chainable `ResolutionResult` (mask/count/summary cheap, `toJson()` lazy rich).

**Current behavior:**
The public surface exposes `query()`/`queryAsync()` returning a chainable `QueryResult` (ADR-0014); there is no resolution surface.

**Desired behavior:**
- `resolve(candidates, query)` and `resolveAsync(candidates, query)` mirror `query()`/`queryAsync()` in input normalization (candidates as Buffer/string/object, query as string/object) and in thread semantics (`resolveAsync` computes off the main thread).
- Both return a chainable `ResolutionResult`: `mask()` (`0` no resolution, `1` resolved, `2` invalid), `count()`, and `summary()` derived cheaply from the native mask; `toJson()` is the one lazy native rich call returning per-candidate `{outcome, winner, values, applicable}`.
- Same query shape as `query()`: `spatial`/`where`/`excludeRuleIds`.
- `query()` and its mask are untouched; TypeScript types are exported.

**Key interfaces:**
- The engine/query surface — a resolve entry point mirroring the existing query one (ADR-0014's "one native evaluation, many views" contract)
- `ResolutionResult` — the chainable wrapper with cheap derived terminals and a lazy rich JSON terminal
- The napi binding — resolve (and resolveAsync) native calls plus the resolution mask/rich payload

**Acceptance criteria:**
- [ ] `resolve()` mask/count/summary match the native evaluation semantics
- [ ] `toJson()` is lazy (mask-only callers pay no rich cost) and returns per-candidate outcome/winner/values/applicable
- [ ] `resolveAsync()` returns `Promise<ResolutionResult>` equivalent to `resolve()` and computes off the main thread
- [ ] `query()` behavior is unchanged
- [ ] TypeScript type exports exist for `ResolutionResult`
- [ ] Core tests, node smoke/integration suites pass; clippy green

**Out of scope:**
- `resolveFields` subset selection
- Changing `query()`'s return type
