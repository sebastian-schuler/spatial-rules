# Temporal conditions: query `at` + whole-clause `$activeAt` over scalar rule window properties

Type: task
Status: ready-for-agent

## Question

Per ADR-0017, implement temporal conditions as a property-filter predicate:

- `Query` gains a top-level `at` (ISO-8601), parsed to a naive-local day-of-week + time-of-day; required (`SR_INVALID_QUERY`) when a `$activeAt` predicate is present; a present-but-unused `at` is parsed and validated.
- `$activeAt` is a new `WhereExpr` variant composable at any clause position, naming the rule's window fields: `{ "$activeAt": { "daysOfWeek": "<field>", "startHour": "<field>", "endHour": "<field>" } }`.
- Admission: start-inclusive / end-exclusive, midnight-wrap when `startHour > endHour`; a missing temporal field or `daysOfWeek = 0` → non-match; `startHour == endHour` → an empty window (never active).
- Rule windows are ordinary scalar properties (`daysOfWeek` Int bitmask Mon=1..Sun=64; `startHour`/`endHour` Int 0..=23); no reserved keys, no `Rule` schema change.

Tests: `at` parsing/validation, window boundaries (inclusive start / exclusive end, midnight wrap), day membership, missing-fields non-match, empty window, `$activeAt` composition under `$and`/`$or`/`$nor`, at-required error.

Run: `cargo test --workspace` and `cargo clippy --workspace --all-targets` — green before commit.

## Agent Brief

**Category:** enhancement
**Summary:** Add query-supplied time (`at`) and a `$activeAt` where-predicate that admits rules whose scalar window properties contain the query time.

**Current behavior:** No time exists in the engine; the query path is deterministic and pure; `WhereExpr` supports `$and`/`$or`/`$nor` and field predicates over scalar `PropertyValue`s.

**Desired behavior:**
- The query carries an optional ISO-8601 `at`; when any `$activeAt` clause is present, `at` is required (`SR_INVALID_QUERY`).
- `$activeAt` admits a rule iff the rule's `daysOfWeek` bitmask contains the `at` day-of-week and `at`'s hour is in `[startHour, endHour)` (wrapping at midnight).
- Windows are ordinary scalar rule properties; nothing in `Rule`'s schema changes.

**Key interfaces:**
- `Query` — a new `at` member (parsed from the JSON query shape) + the `from_json` validation.
- `WhereExpr` — a new `ActiveAt { days_of_week_field, start_hour_field, end_hour_field }` variant evaluated against the query `at`.

**Acceptance criteria:**
- [ ] A rule whose window contains the query `at` is admitted; one outside the window is not
- [ ] Midnight-crossing windows (`start > end`) wrap correctly
- [ ] `startHour == endHour` yields an empty window (never active); a missing window field or `daysOfWeek = 0` never admits
- [ ] `$activeAt` composes under `$and`/`$or`/`$nor` at any clause position
- [ ] `at` is required when a `$activeAt` clause exists (`SR_INVALID_QUERY`); a malformed `at` is rejected; a present-but-unused `at` is allowed and validated
- [ ] `query()` and the mask hot path are unchanged
- [ ] `cargo test --workspace` and `cargo clippy --workspace --all-targets` are green

**Out of scope:**
- Temporal indexing
- Holidays; timezone offsets; sub-hour precision
- Reserved window keys
