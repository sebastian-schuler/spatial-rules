# Persisted rulesets: canonical JSON format, recompile on load

Rulesets serialize to and load from a canonical JSON form to enable deploy-time precompilation: validation errors surface at build time instead of on the first request, and pods boot from a deterministic canonical ruleset rather than arbitrary input GeoJSON. The persisted form holds the canonical **rules** (validated/canonicalized geometry + typed properties), not the compiled indexes — on load the full compile (envelopes, rstar index, property index, prepared geometry) re-runs through the existing build path and publishes via the `Engine` atomic swap, so a failed load leaves the old ruleset intact. Recompile is ~22 ms for the §43 workload, small enough that a fully-compiled binary format (serde across the rstar tree + `EqualityIndex`, format versioning, load-time re-validation of untrusted bytes) is not worth its complexity; canonical JSON is human-readable and diffable. A fresh `Ruleset.id` is assigned at load — the id and the global `NEXT_RULESET_ID` counter are never persisted, avoiding cache-key collisions in the per-thread prepared-geometry cache (ADR-0010). This adds `serde` (derive) to the workspace for the rule/property types; `geo_types::Geometry` and `geojson` are already serde-serializable in the pinned versions. Invalid canonical input reuses the `SR_*` error model.
