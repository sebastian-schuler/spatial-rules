# Additional predicates and quantitative overlap

The DE-9IM predicate set (ADR-0008) grows to `covers`, `covered_by`, `touches`, `overlaps`, in the same candidate-relates-to-rule direction as the existing `intersects`/`contains`/`within`. `covers` = `matrix.is_covers()`, `touches` = `matrix.is_touches()`, `overlaps` = `matrix.is_overlaps()` (all present in geo 0.33); `covered_by` has no geo helper and is matched as a custom 4-pattern DE-9IM (`T*F**F*** | *TF**F*** | **FT*F*** | **F*TF***`) on the candidate→rule matrix. turf remains the cross-check oracle (ADR-0008): the suite gains `@turf/boolean-covers` and `@turf/boolean-touches` (`boolean-overlap` already pinned). Distance predicates stay out of scope (Initial-plan §3/§39 — nearest-neighbor is a non-goal, and distance is a metric/CRS feature, not DE-9IM). Quantitative overlap — `overlapArea` and `overlapRatio` — is returned per matched (candidate, rule) pair on the rich path only: `overlapRatio = geodesic_area(candidate ∩ rule) / geodesic_area(candidate)` (dimensionless [0,1]) and `overlapArea` in m², both computed from a `geo::BooleanOps` intersection measured with `GeodesicArea` (spherical), so WGS84 lon/lat is never treated as planar (Initial-plan §14). The hot-path `Uint8Array` mask is unchanged; overlap output is opt-in via an `includeOverlap: true` query flag honored by `queryRich`.
