# Prepared-geometry caching: per-call preparation until geo ≥ 0.34

The query pipeline prepares each rule's `PreparedGeometry` once per `Ruleset::prepare` call (~5 ms for 30 rules, amortized over the batch) rather than caching it across requests. The algorithm ladder shows preparation is the dominant ~23× lever (E/F benches), but `PreparedGeometry` is `!Send + !Sync` in geo 0.33, so a cross-request cache would need unsafe self-referential storage or a narrower `Ruleset` `Send + Sync` contract — which ADR-0007's shared `Arc<Ruleset>` forbids. Preparation therefore stays local to the `PreparedQuery`, at a single construction site in `Ruleset::prepare`. Revisit when geo ≥ 0.34 ships the `Send` fix: cache prepared geometries per thread keyed by the ADR-0007 ruleset version, closing the ~1.6 s / 10k-rules scaling risk without changing the query pipeline's interface (the geo 0.33 → 0.34 upgrade is itself a separate change to evaluate for breaking API surface first).
