# Prepared-geometry caching: thread-local owned geometries on geo 0.33

The query pipeline prepares each rule's `PreparedGeometry` once per `Ruleset::prepare` call (~5 ms for 30 rules, amortized over the batch); the ladder shows preparation is the dominant ~23× lever (E/F benches). `PreparedGeometry` is `!Send + !Sync` in geo 0.33 because its `GeometryGraph` holds an `Rc` — not because it borrows. A sound cross-request cache is nonetheless possible now: cache the **owned** form `PreparedGeometry<Geometry<f64>>` (built via `PreparedGeometry::from(rule.geometry.clone())`) in a `thread_local!` keyed by ruleset identity. Owned prepared geometries carry no borrow of the ruleset, and `thread_local!` accepts `!Send` types, so no self-referential storage or `Send + Sync` narrowing is needed; the price is one geometry clone per thread per ruleset. When geo ≥ 0.34 ships the `Rc → Arc` (`Send`) fix, the clone disappears by storing prepared geometries in the shared `Arc<Ruleset>` itself. The decision to adopt the cache is recorded separately when implemented (the geo 0.33 → 0.34 upgrade is its own change to evaluate for breaking API surface).
