# Predicate semantics: DE-9IM authoritative, turf as cross-check oracle

`intersects`, `contains`, and `within` are defined by DE-9IM via geo `Relate`: `intersects` = matrix ≠ `FF*FF****` (touching boundaries → true); `contains` = `T*F**F***` and `within` = `T**F*F***` (full containment; touching from outside → false). Geo's DE-9IM is authoritative; turf.js is an independent oracle for cross-checks, never the spec — a JTS-faithful turf major (v6, JSTS-based) is pinned in devDependencies, both sides are normalized to a shared precision before comparing, invalid/degenerate inputs are excluded (validated upstream per ADR-0005), and any remaining disagreement is investigated against JTS/GEOS and recorded as a known quirk. Predicates assume valid inputs; there is no re-validation in the hot path.

Extended by ADR-0012: `covers`, `covered_by`, `touches`, and `overlaps` join the DE-9IM set in the candidate→rule direction, and overlap area/ratio semantics (geodesic, m², rich-path only) are defined there.

Known turf v6 quirks (recorded per ADR-0008; geo/DE-9IM is authoritative, verified against JTS/GEOS): turf has no `covers`/`covered_by` boolean module, so the suite cross-checks them as `contains`/`within` (equivalent for area geometries). turf v6 `booleanOverlap` reports `true` for boundary-touch (`touching_edge`, `touching_corner`) where DE-9IM `overlaps` is `false` (no interior intersection); turf v6 `booleanTouches` reports `true` for identical polygons where DE-9IM `touches` is `false` (interiors intersect). These three cases are excluded in the cross-check and verified by hand against DE-9IM.
